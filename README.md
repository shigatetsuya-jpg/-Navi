# ワセサークルナビ

スマートフォン対応のサークル検索サイトと、管理者認証付きの運営画面です。旧版の画面イメージに合わせ、淡いピンクベージュ、赤橙色のアクセント、上部検索、時間割表、カテゴリ別カード、比較導線、FAQを配置しています。団体情報は登録されたデータだけを表示します。Node.js 24 の標準機能だけで動作し、DB は SQLite です。

## 起動

```powershell
$env:ADMIN_SETUP_TOKEN = "十分に長いランダムな初回設定キー"
node server.mjs
```

`http://localhost:3000` を開きます。初回は `/admin.html` で初期設定キー、管理者メール、12文字以上のパスワードを登録します。セットアップ後は初回キーを環境から外して構いません。初回管理者が登録されると、公開経路から追加の管理者登録はできません。

自動テストは Node.js 24 で `node --test` を実行します。外部サービスを使わず、使い捨てSQLite DBで公開・管理APIを確認します。

Windowsでキーを作る例:

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

本番では必ずHTTPSを使い、`ADMIN_SETUP_TOKEN` は初回セットアップ時だけ設定してください。`DB_PATH` は永続ディスク内に指定します。既定は `./data/shinkanavi.sqlite` です。

## 機能

- 公開団体の複合検索、詳細、情報確認状況、更新日表示
- 閲覧はゲストに開放。アカウントは事前登録でき、申し込み時に個人登録へ進むことも可能
- 個人アカウントと団体アカウントを分離し、団体登録は運営確認後に公開
- 個人マイページでイベント申込状況を確認し、申込取り消しが可能
- 団体画面で体験会・イベントを作成し、定員、受付状態、開催日時を管理
- 団体ごとに申込を分離し、承認・見送りを記録。満員後の申込はキャンセル待ちに入れ、空きが出ると繰り上げ
- キャンパスは早稲田・西早稲田・所沢・戸山を標準候補として表示。登録データに別名がある場合も選択肢に追加
- 時間割は初期状態を未選択とし、参加できるコマだけをブラウザの localStorage に保存して活動時間と照合
- 検索結果のサークルが活動する曜日・時限を時間割形式で可視化。PCでは各マスに団体名、スマートフォンではマス内の件数と選択した時間帯の団体一覧を表示
- お気に入りをブラウザに保存（アカウント不要、端末間同期なし）
- 2〜4団体の条件比較、確認状況や更新日を考慮したおすすめ順／新着順
- 管理画面で新規登録、編集、複製、公開切替、非公開化
- 管理画面で利用者一覧を確認し、本人の申込履歴とともに削除（団体のみの管理者の場合は団体を非公開化し、イベント受付を終了）
- CSV/JSONのプレビュー、必須項目検証、大学名＋団体名による重複候補照合、行単位のエラーと再試行、CSV出力
- SQLite保存、管理API認証、scryptパスワードハッシュ、HttpOnly/SameSiteセッションCookie

活動時間が不明な情報は登録済みの値だけで照合します。未確認・未登録は画面に表示されます。架空のサンプルは `public/sample.csv` と `public/sample.json` にあり、非公開として用意しています。

## 一括登録

管理画面の「一括登録」から `public/sample.csv` または `public/sample.json` の形式で読み込みます。CSVの先頭行は項目名です。必須項目は `name`（団体名）と `university`（大学名）。同一大学の同一団体名が登録済みなら重複候補となり、新規登録モードではスキップされます。更新モードでは一致した行だけを更新し、異なる名前の行は新規追加します。エラー一覧から失敗行のみ再試行できます。

管理画面で新規登録する場合、大学名は「早稲田大学」、キャンパスは早稲田・西早稲田・所沢・戸山から選択済みで始まります。必要に応じて大学名やキャンパスを変更でき、一括登録の既存データに含まれる別のキャンパス名も保持されます。

## アカウントと運営フロー

ゲストは検索・比較・イベント閲覧まで登録不要です。申し込みボタンから個人登録またはログインへ進み、登録後に申込を送信できます。団体は登録時に団体情報も申請し、運営者が確認・公開してからイベント受付を開始できます。全体管理者は `/admin.html`、個人・団体の利用者は `/dashboard.html` を使用します。

申込では氏名、大学、学年、任意メッセージを担当団体に表示します。メールアドレスは団体画面に返しません。メール設定後は、学生へ申込受付・承認・見送り、団体の担当者へ新規申込を通知します。メールには申込者の氏名やメッセージを載せず、詳細はログイン後に確認します。利用者はマイページでも申込状態を確認でき、団体は一覧から承認・見送りを処理します。

### メール通知（Resend）

送信には `RESEND_API_KEY` と、Resendで確認済みの送信元を指定する `EMAIL_FROM` が必要です。どちらもRenderの環境変数に設定し、キーをソースコードへ保存しないでください。ドメインのDNS確認とサービス側の送信元確認が終わるまでは通知は無効です。通知はSQLiteの送信キューに保存され、一時的な送信失敗は再試行します。8回失敗した通知は `failed` になります。

対象は申込受付、団体への新着申込、承認・見送り、キャンセル待ちからの繰り上げです。現在の登録画面にはメールアドレス確認機能がありません。誤入力先へも通知が届く可能性があるため、実利用前にメールアドレス確認の仕組みを追加し、正しい送信先だけに通知してください。

## セキュリティと負荷への備え

- パスワードは個別ソルト付き scrypt ハッシュとして保存し、ログイン Cookie は HttpOnly・SameSite=Strict に設定。セッションDBにはトークンのハッシュだけを保存
- 団体管理APIは担当団体のIDを毎回照合し、申込一覧で他団体の情報を取得できないようにする
- 申込はDBトランザクションとイベント・利用者の一意制約で二重送信を防ぎ、定員超過分はキャンセル待ちに回す
- ログイン・登録の試行制限は現在プロセス内メモリで管理するため、複数インスタンス運用前に共有ストアへ移す必要がある
- メール通知コードはあるが、送信元設定とメールアドレス確認は未完了。二要素認証、利用規約・プライバシー案内、データの保存期間・削除依頼窓口も公開前に整備が必要
- 小規模な初期運用ではSQLiteを使用。アクセス増加や複数インスタンス運用に移る段階でPostgreSQL等へ移行し、バックアップ・監視・申込負荷の確認を追加する

## 本番デプロイ（Render）

`render.yaml` はBlueprintとして使えます。Node.js 24.22.1のWebサービス、シンガポールリージョン、`/health` ヘルスチェック、1GB永続ディスク（SQLite用）、HTTPS付き `onrender.com` URLを設定しています。

1. このプロジェクトは `shigatetsuya-jpg/-Navi` リポジトリの `shinkanavi-render` ブランチに登録します。旧版はGitの履歴に残しつつ、新版のファイル一式でこのブランチを置き換えます。
2. Render Dashboardで「New」→「Blueprint」を選び、`shigatetsuya-jpg/-Navi` を接続して、デプロイ対象ブランチを `shinkanavi-render` に指定し、`render.yaml` を読み込みます。
3. `ADMIN_SETUP_TOKEN` を入力してBlueprintを適用します。これは初回管理者登録専用の秘密値です。初期設定が終わったらRenderのEnvironmentから削除します。
4. Renderが表示する料金と構成を確認してから、デプロイを確定します。Freeサービスではディスクが永続化されないため、この構成は有料の最小Webプランを指定しています。
5. Renderが発行した `onrender.com` URLを開き、`/admin.html` から管理者を登録して、確認済みの実データを登録します。

2026-10-29時点の概算は、Webサービスが月7米ドル、1GBディスクが月0.25米ドルで、**合計月7.25米ドルから**（税・追加使用量・為替手数料別）です。Hobby workspace自体は無料ですが、永続ディスクを使うWebサービスは有料プランが必要です。ディスク利用中は一度に1インスタンスで動作し、再デプロイ時に数秒の停止があり得ます。料金は確定前にRender画面で再確認してください。

参照: [Render Blueprint](https://render.com/docs/blueprint-spec)、[永続ディスク](https://render.com/docs/disks)、[料金](https://render.com/pricing)、[Node.jsバージョン設定](https://render.com/docs/node-version)。RenderのURLは環境変数 `RENDER_EXTERNAL_URL` から取得します。`PUBLIC_SITE_URL` を設定すると独自ドメインに切り替えられます。旧GitHub Pages版は公開停止済みです。

## 仕様上の注意

- `updated_at` はDBのUTC時刻です。画面では日付部分を表示します。
- 外部公式フォーム/SNSを中心とする方針を検討中です。開発枝には会員・サイト内申込もあるため、本番へ一括反映せず公開範囲を確認します。
- 初回DB構築は `migrations/001-init.sql` で行い、適用版を `schema_migrations` に記録します。将来の列変更には連番マイグレーションを追加してください。
- 開発枝にはTS名義の問い合わせフォームと規約5ページがあります。正式公開前に文面・保存期間・返信経路の確認が必要です。

## 検索エンジン向け設定

- トップページに日本語の説明文、canonical URL、Open Graph情報を設定します。
- /robots.txt と、公開・確認済みサークルの /circle/:id を含む /sitemap.xml を動的生成します。サークル紹介ページは検索エンジンが本文を読めるHTMLとして配信します。
- ログイン、マイページ、管理画面には 
oindex を指定します。
obots.txt ではページの巡回を遮らず、検索結果への登録だけを抑制します。
- Google Search Consoleで所有権確認後、https://<公開ホスト>/sitemap.xml を送信してください。
