# 通知送信元の準備

関連：T02。2026年11月7日確認。運営表示TS、本人氏名・問い合わせメール非公開。送信元メールは受信者に見えるため、非公開の問い合わせアドレスとは分けて決める。

## 調べた公式仕様
- [Resendのドメイン追加](https://resend.com/docs/add-a-domain)：自分で管理し、DNSを設定して確認できるドメインを使う。送信専用サブドメインが推奨される。
- [resend.devの制限](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)：標準のonboarding@resend.devはResendアカウント本人のアドレス宛てのテスト用。学生・団体へ一般送信するための代用にはならない。

学校のメールアカウントを持っていることと、そのドメインのDNSを管理できることは別。大学ドメインを自分で確認できなければ、Resendで学校メールを送信元に設定しない。

## 決まっている構成と未確認項目
Resend送信コードは実装・代替送信で検証済み。Resendアカウントの有無、管理できるドメイン、DNSの権限、送信元、APIキーの準備は未確認。ユーザーより独自ドメイン未取得と確認済み。Resendアカウント・送信元・APIキー・DNSの準備は未確認。

ドメインを既に持っていれば、メール用サブドメインに必要なDNS設定を準備する。持っていない場合は、取得候補と初年度・更新年の料金を調べて承認を得てから取得する。取得を勝手に進めない。別の既存送信サービスを使う場合も、権限・本人の非公開メールを受信者へ見せない条件を確認する。

## 本人宛て到達テストの承認用チェック
- 送信元・宛先・件名・本文を明示する。APIキーはチャットやGitHubに書かない。
- まず本人が管理するテスト宛先1件へ、合成データの確認メールを送る。
- Resendへ渡すのは送信元・宛先・メール本文。実名・実申込本文は含めない。
- Resend受理、実際の受信、迷惑メール、確認リンク、画面の確認済み表示を分けて記録する。API成功だけで到達済みと報告しない。
- 学生・団体への送信は本人宛て試験と別の対象として承認し、ドメイン確認後に実施。
- 反映時はEMAIL_DELIVERY_DISABLED=1を保ち、設定と宛先をレビューしてから明示的に解除する。

## 追加で修正したこと
プレーンテキストでも承認・見送り・繰り上げ・キャンセル待ちを本文に表示。HTMLエスケープした文字をプレーンテキストへ流用しない。400等の恒久的な送信拒否は即失敗、429・一部の競合・タイムアウト・5xx等は既存の上限付き再試行に回す。プロバイダーの生エラー本文は保存・ログ出力せずHTTPステータスだけを記録する。

実際の送信サービスとの疎通、ドメイン確認、メール到達は未実施。自動テストは外部通信しない代替送信を使用する。
