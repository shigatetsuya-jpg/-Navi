# 正式公開前にTSが確認する事項

規約類はたたき台であり、法令適合の保証ではない。文面は現在の実装に合わせているが、次は実際の運用・委託条件に基づき確定する。現在の版番号は2026-11-07-draft。公開するときは版を確定し、登録時の同意記録と一致させる。

- 運営者表示はTS。個人の本名・住所・メールは公開しない。将来の有料提供で追加の法定表示等が必要かは販売形態に応じて確認。
- 問い合わせを誰が・どの頻度で管理画面から確認し、返信するか。現実の返信経路は未確定で、自動メール返信を約束しない。
- 収集する項目は本当に必要か。大学・学年・氏名の必須性、既存申込機能を提供する範囲、公式フォームと分担する情報を見直す。
- Render・Resendの処理地域、委託先の保持・再委託・事故対応、第三者提供/外国での取扱いの説明を実契約で確認。
- 問い合わせ・認証履歴・送信履歴・ログ・バックアップの保存期間を確定。退会で削除されるデータと残る複製を区別し、復元時に退会した利用者の情報が復活しない運用が必要。
- 著作権・画像使用、団体担当権限、掲載同意、学校公認の根拠を確認。団体情報の確認済みと大学の保証は別。
- 「早大生認証済み（早稲田メール確認）」は大学ドメインのメール所有確認で、教職員等も所有しうる。学籍や現在の在学を証明する印ではない。誤認があれば表示名を変更する。
- 規約変更の周知方法と再同意が必要になる条件を決める。現行は登録・団体申請・管理者申請・編集時の版と日時を記録するが、既存全会員への強制再同意は未実装。
- 個人会員のメール確認が必須になったため、旧会員にも確認手順を案内する。メール未設定で会員機能を使える抜け道は作らない。
- 学校との公式な関係をうたわない。トップだけでなく全ページのフッターに非公式・個人運営を明示。
- CSRFのOrigin/Fetch Metadata/JSONチェックとSameSite Cookieの前提、単一プロセス内の試行制限（再起動でリセット）、本番バックアップ・復元・監視・鍵管理を確認。複数インスタンスにする前に制限を共有ストアへ移す。

参照：[個人情報保護委員会・法令ガイドライン](https://www.ppc.go.jp/personalinfo/legal/)、[通則編](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)。2026年11月7日に確認。個別の法的判断が必要な場合は専門家に確認する。

- イベント通知は独立した初期オフの希望設定。通知の種類・設定日時・同意版・重複防止記録の保持期間も決める。退会で連動削除し、通知停止だけでは重複防止記録を残す。
