# 掲載確認基準・運営チェックシート

関連：G0 → S2 → S2.M1 → S2.M1.I1 → T05。これは準備資料であり掲載の承認そのものではない。

## 最初に揃える情報
団体名、大学、カテゴリ、主な活動内容、活動キャンパス、活動時間（不明なら不明）、費用と徴収頻度、規模（基準日を付ける）、初心者・兼サークルの参加条件、団体の公式サイトまたは公式SNS、体験参加方法。任意の紹介文や画像は利用許諾の範囲も記録する。

公開情報の出典と団体から直接提供された情報を区別する。公開されているだけで文章・画像の転載許可があるとは扱わない。要約を作る場合も団体への確認待ちとする。代表者個人のメール・電話・会員情報を公開欄へ記入しない。

## 確認手順
1. 団体の公式情報を確認し、出典URLと確認日を記録する。
2. 申請者が団体の情報を更新できる立場か、公式窓口との対応で確認する。メール所有確認だけで団体の代表権・学校公認を認証したとはみなさない。
3. 掲載文と公開項目を団体に提示し、掲載・画像等の利用・更新連絡への同意を記録する。連絡の送信は事前承認後。
4. 活動内容・場所・費用・時間・参加条件・体験参加方法を照合。不明な値を架空の値で埋めない。大学公認は根拠がある場合だけ記載する。
5. 確認担当者が不適切な勧誘・虚偽情報・個人情報の混入・危険なリンクを点検する。
6. 確認記録と掲載許諾が揃っても、公開対象の追加はユーザーの明示承認後に行う。
7. 公開後は掲載内容、検索、詳細、参加経路を確認。変更・訂正の依頼先を伝える。

## 記録のひな型
- 候補ID／団体名／大学：
- 出典URL／情報確認日：
- 不明・確認待ちの項目：
- 団体の確認状況／確認方法：
- 掲載内容への同意日／同意範囲／証跡の保管先：
- 公開承認日／承認した対象・項目：
- 確認担当者／次回確認予定日：

証跡や個人連絡先はアクセスを制限した保管先で管理し、このGitHubリポジトリに入れない。テンプレートCSVは個人情報を含めない候補・進捗用。

## 状態と更新
内部管理の状態は候補→情報整理中→団体確認待ち→許諾済み→公開承認待ち→公開→更新確認中。現行DBのpublished/verifiedと同じ状態体系ではないため、記録を見ずに一括公開しない。
情報鮮度の90日は現時点の仮説。新歓直前はイベント日時・締切・参加方法を優先して再確認する。訂正依頼・掲載停止依頼は窓口で受け付け、対象と本人性を確認して対応する。
