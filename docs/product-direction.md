# 初期サービスの役割見直し：比較・イベント案内・公式窓口

2026年11月7日。ユーザーの最新の問題提起を受けた推奨案。ドメイン購入を止め、導線と役割を先に決める。既存予約機能を削除・公開変更する承認とは扱わない。

## 中心の利用体験
団体を探す → 比較して選ぶ → 団体詳細でイベントと連絡窓口を見る → 公式Googleフォーム等で申し込む／InstagramやLINEへ進む。
イベントとSNSは二者択一ではない。イベント参加と、質問・団体との接点作りを別のボタンにする。

| 利用者がしたいこと | 案内先 | サイト側で提供する情報 |
|---|---|---|
| 団体を比較・選択 | 団体比較 | 活動内容、時間、場所、費用、規模、参加条件、確認日 |
| 体験会へ参加 | イベントごとの公式フォーム | 日時、場所、申込期限、募集定員、受付状態、最終確認日時 |
| 団体へ質問 | 団体が指定した公式Instagram・公式LINE等 | 用途と外部サイトへ移ることを明記 |
| 継続して情報を得る | お気に入り・公式SNS・任意の通知 | 新イベント／期限前／開催前のどれを通知するか先に決める |

## 比較で最初に直すこと
「比較する」を文字で表示。選択済み団体名と解除ボタンを出し、2〜4団体を横並びにする。活動時間、費用、規模、参加条件を先頭に置く。項目の違いを強調し、同じ項目を隠せるようにする。
未登録をゼロ円・参加条件なしと扱わない。月会費と年会費を同じ数値として順位付けしない。雰囲気は根拠のある団体紹介で表現し、ランキングやレビューを先に作らない。

## 外部フォーム方式の境界
Googleフォームへリンクするだけでは、実際の申込完了・承認・残席は取得できない。「定員30名」は表示できても「あと5席」や「予約完了」は同期なしでは表示しない。初期は団体が更新する受付状態と最終確認日時を示す案とする。クリック数は申込者数ではない。
イベント通知も外部フォームの予約結果通知とは別。新イベント告知、開催前／締切前のリマインドの優先順位はユーザーに確認中。個別の予約結果は当面団体・公式フォーム側の対応と分担する案。
GoogleフォームURLを開くだけで、学生の氏名やメールを自動入力・転送しない。本人が外部サイトで入力する前に案内先を明確にする。

## 連絡先の整備
既存のsnsフィールド1本ではInstagramとLINEを独立して扱えない。公式Instagram、公式LINE、その他公式サイト、イベントごとの申込URLを分けて管理する設計へ進む。一般公開のグループLINE招待URLが適切かは団体の同意と運用を確認。個人アカウントや許可のないグループ招待を転載しない。

## 既存実装の扱い
検索・比較・時間割・団体管理・イベント情報は活かす。サイト内申込、学生登録、メール所有確認、定員のトランザクションは既存開発成果として保管し、初期の必須導線から外す案。本番DBや登録情報を削除せず、予約方式の大きな変更を未承認で反映しない。
PR #2〜#4の予約・メール前提の一括本番反映は保留。名称変更済み本番を維持し、新しい役割に沿った差分だけを改めてレビューする。

## 目標と計測の変更案
初期は「確認済み掲載数」「イベント情報の鮮度」「公式申込先への遷移」「問い合わせ先への遷移」を分ける。遷移は申込・入会・実参加と呼ばない。実際の参加成果は団体の協力と同意に基づく集計で検証する。
個人登録200人等の旧KPIは予約方式が前提の仮説だったため、今の方針決定後に再設定する。4月の実用化・普及、2027年の初回売上という最上位Goalは維持する。

## 当面の順番
1. 比較選択と比較表を改善してスマホ・PCで確認。
2. イベント情報と公式連絡先の項目・更新担当・外部申込導線を確定。
3. 団体画面でその情報を無理なく登録・更新できるよう実装。
4. 合成データのデモで、探す→比べる→イベント／連絡先へ進む操作をユーザーに見せる。
5. 公開・外部連絡を承認後に、ユーザーが知り合いの団体へ使用交渉。
6. 必要性が確認できた通知方式とドメイン取得を改めて決める。
