# 試用検証と公開前の確認

関連：T02、T03、T04、T11、T13。次の本番操作や試用者への連絡は承認後。以下のローカル検証は外部送信なしで実施する。

## 学生が試すこと
- 登録なしで条件検索し、団体の時間・費用・規模・参加条件を比較できるか。
- 検索結果0件とサイト全体の掲載0件を混同せず、次に何をすればよいかわかるか。
- 登録、メール確認（テスト用送信）、申込、待機列、取消、状況確認を行えるか。
- 氏名や申込メッセージが誰に見えるか理解できるか。

## 団体が試すこと
- 団体登録、運営確認待ち、イベント下書き、受付開始、申込確認、判断、受付終了。
- 他団体の情報を見たり変更したりできないこと。
- 通知が届かない場合でも画面で申込状況を確認できること。

## 運営が試すこと
- 掲載内容と許諾の確認、内部連絡先と公開項目の分離、公開承認の記録。
- 保存先・バックアップ・復元手順、アカウント復旧・データ削除の対応。
- 問い合わせ先、利用条件・個人情報の説明、通知の未整備項目。

## 今回の同時申込テスト
使い捨てSQLiteと合成アカウントのみ使用。外部へのメール送信なし。
- 定員3人へ20人同時申込：受付3人、待機9人（定員の3倍が上限）、409応答8人。
- 同じイベント・利用者で8回同時送信：1件だけ成功、7件は重複として409。
- 過去日時のイベント：409で拒否、申込行は追加されない。
この結果は単一プロセスにおける整合性検証であり、性能上限・本番同時接続数を示さない。

## 試用結果の記録
日時、タスクID、検証環境、成功/失敗、迷った操作、所要時間、修正・担当・再確認日を記録する。実参加は承認件数と別に集計する。個人情報・申込本文はGitHubへ保存しない。
